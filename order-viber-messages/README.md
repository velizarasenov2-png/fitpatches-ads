# Viber съобщения за поръчките (BulkGate + Shopify + BigArena)

На всеки 15 минути (08:00–21:00) системата проверява поръчките от последните 14 дни и праща на клиента съобщение.

**В момента: само SMS** (кратък текст на латиница, 1 SMS). `VIBER_SENDER` остава празно. Viber се включва по-късно, без промяна в кода: регистрирате Viber подател и шаблони в BulkGate и попълвате `VIBER_SENDER`. Тогава първо се пробва Viber, а SMS отива само ако клиентът няма Viber.

| Кога | Съобщение |
|---|---|
| 5 мин. след поръчката | Благодарим за поръчката + продукт, сума, офис/адрес, телефон за въпроси |
| Пратката е в офиса на Спиди/Еконт | Чака Ви в офиса + адрес на офиса, товарителница, сума |
| 2 дни в офиса, още не е взета | Напомняне |
| 4 дни в офиса, още не е взета | Последно напомняне: „иначе куриерът ще я върне“ |
| До адрес: куриерът тръгва днес | „Днес куриер ще Ви донесе…“ + товарителница, сума |
| До адрес: неуспешна доставка | „Куриерът не успя да Ви открие…“ + телефон |
| До адрес, но куриерът я е оставил в офис | Напомнянията след 2 и 4 дни |

Във всяко съобщение пише „розовите лепенки FitPatches за намаляване на апетита“. Номер на поръчката не се показва. Телефонът за въпроси е 0887459494.

**Не се пращат съобщения:**
- при анулирани поръчки и дубликатите от ъпсела (`fp-upsell-replaced`);
- при взети, платени или върнати пратки;
- извън часовете 08:00–21:00.

Всяко съобщение се праща само веднъж. Кое е изпратено се пази в поръчката, в metafield `fitpatches.msgs`.

## Откъде знае къде е пратката

1. **BigArena** (`my.bigarena.net/tracking/...`), същата страница, към която води линкът за проследяване в Shopify.
   - Спиди: „Подготовка за предаване на клиент в офис“, „Доставка на клиент“, „Отказване от получател“, „Неуспешна доставка“ и др.
   - Еконт: последното сканиране в офиса на получателя, „Връщане на пратката“.
2. **Shopify** като проверка. Ако поръчката е анулирана, платена или Shopify е отбелязал връщане, съобщенията спират, каквото и да показва BigArena. Ако BigArena не отговори, се ползват статусите от Shopify.

## Пускане

### 1. BulkGate (праща и Viber, и SMS)
За SMS стигат стъпки 1 и 2. Стъпки 3–5 са само за Viber, по-късно.

1. Регистрация на bulkgate.com и зареждане на кредит.
2. **Modules & APIs → Advanced API → създаване на приложение.** Взимате **Application ID** и **Application token**.
3. **Viber подател (Viber Business).** За заявката трябват:
   - име на фирмата, адрес, телефон, сайт;
   - юридическо име и действителен собственик;
   - описание на фирмата (до 1000 знака) и за какво ще са съобщенията (до 400 знака), без линкове;
   - лого в PNG в 6 размера: 360x280, 256x256, 130x130, 100x100, 65x65, 50x50;
   - подписани формуляри от BulkGate.

   Одобрението е 7 работни дни според помощния център на BulkGate (на страницата с цените пише 14 дни).
4. **Viber шаблони.** Viber изисква съобщенията за поръчки да са одобрени шаблони. Отидете в **SMS & Viber messaging → Viber templates → New template** и регистрирайте 6-те шаблона. Текстовете, ключовете и примерните стойности ги изкарва командата `npm run templates` (вижте и таблицата по-долу). Език: `bg`, тип: transactional.
5. Докато Viber подателят и шаблоните не са одобрени, оставете `VIBER_SENDER` празно. Тогава се праща само SMS, или изобщо не пускайте на живо.

### 2. Shopify приложение
Dev Dashboard → Create app → scopes **read_orders** и **write_orders** → Protected customer data (име, телефон, адрес) → Release → Install на магазина → **Client ID** и **Client secret**.

### 3. GitHub
Settings → Secrets and variables → Actions:

| Secrets | |
|---|---|
| `SHOPIFY_CLIENT_ID`, `SHOPIFY_CLIENT_SECRET` | от Shopify |
| `BULKGATE_APP_ID`, `BULKGATE_TOKEN` | от BulkGate |
| `TEST_PHONE` | вашият телефон, само за теста |

| Variables | |
|---|---|
| `VIBER_SENDER` | одобреното Viber име, напр. `FitPatches` |
| `VIBER_TEMPLATES` | по подразбиране `true` (праща одобрените шаблони); `false` = обикновен текст |
| `LIVE` | `false` → проба, `true` → праща |
| `START_AT` | напр. `2026-10-27T08:00:00+02:00` |

Автоматичното пускане работи само от клона `main`, затова тази папка и `.github/workflows/order-viber-messages.yml` трябва да са слети в `main`.

### 4. Безопасно пускане
1. **Проба:** `LIVE=false`. В Actions → „Viber съобщения за поръчки“ → Run workflow. В лога се вижда коя поръчка какво би получила. Нищо не се праща.
2. **Тест до вас:** `LIVE=true` + secret `TEST_PHONE`. Всички съобщения идват на вашия телефон, по едно от всеки вид за всяка поръчка. Клиентите не получават нищо.
3. **На живо:** изтривате `TEST_PHONE` и задавате `START_AT` на момента на пускане.

При първото пускане клиентите, чиито пратки вече чакат в офис, получават по едно напомняне: това, което им се полага в момента. Благодарност получават само поръчките след `START_AT`.

## Цена
- **SMS (сега):** €0.076 (A1, Vivacom) – €0.089 (Telenor) за SMS от подател 1779, без месечна такса. При ~700 SMS на месец това са около €55–60. Всеки SMS е до 160 знака на латиница, така че е 1 SMS.
- BulkGate Viber (по-късно): €0.0198 с шаблон, €0.03 без шаблон. Viber изисква минимум **€150 на месец** (предплатени, после се харчат за съобщения). При ~300 поръчки на месец това са около 700 съобщения, тоест реално плащате минимума.
- GitHub Actions: безплатно, защото repo-то е публично.

## Viber шаблони

| Ключ | Кога |
|---|---|
| `fp-thanks` | благодарност |
| `fp-office` | пристигна в офиса |
| `fp-office-reminder` | напомняне след 2 дни |
| `fp-office-last` | последно напомняне |
| `fp-address-out` | днес до адрес |
| `fp-address-failed` | неуспешна доставка |

Текстовете са в `src/messages.js` (`viberTemplates`), а `npm run templates` ги показва готови за копиране. Ако промените текст в кода, трябва да промените и шаблона в BulkGate, иначе Viber няма да го приеме.

## Поверителност
Repo-то е публично и логовете на GitHub Actions се виждат от всеки. Затова в лога се пишат само номер на поръчка и вид съобщение, без имена, телефони и адреси. `PRINT_TEXTS=true` ползвайте само на компютър.

## Разработка
```bash
npm test                                  # 32 теста
node --env-file=.env src/run.js           # едно пускане с настройките от .env
```

`src/`:
- `run.js`: едно пускане;
- `decide.js`: кое съобщение се полага;
- `messages.js`: текстовете;
- `bigarena.js`: проследяването;
- `order.js`: данните от поръчката;
- `bulkgate.js`, `shopify.js`: връзка с BulkGate и Shopify.

GitHub спира автоматичните пускания в публично repo, ако 60 дни няма никаква промяна в него. Тогава ги включвате пак от Actions.
